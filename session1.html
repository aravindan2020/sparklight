Topic 2 · 30 minutes

UniFlow as a real-world problem

A university has many students, courses, lecturers, and deadlines. A manual approach is slow and prone to duplicate, missing, or inconsistent information. UniFlow centralizes the work.

Common challenges

  • Duplicate student IDs during admission
  • Students registering for unavailable courses
  • Attendance records spread across paper sheets
  • Late or incorrect result calculations
  • Reports taking too long to prepare

What UniFlow improves

  • Fast retrieval of a student record
  • Consistent validation at data entry
  • Automatic calculations and summaries
  • Clear audit trail for academic records
  • Timely reports for staff and students

Computational thinking

SkillMeaningUniFlow example
DecompositionSplit a large problem into manageable parts.Separate admission, registration, attendance, and examination.
Pattern recognitionNotice repeated structures or rules.Every student form needs ID, name, department, and contact number.
AbstractionKeep essential information; hide unnecessary detail.A Student record stores academic details, not the colour of their backpack.
Algorithmic thinkingDefine exact steps to reach a result.Check ID → validate mobile → save record → show confirmation.
Example: “Find students with low attendance” becomes: retrieve attendance totals → calculate percentage for each student → compare with 75 → display students below 75%.
Topic 3 · 20 minutes

The Input → Process → Output (IPO) model

IPO is a simple model for describing a program. It prevents us from jumping straight into code: first identify what enters the program, then what it does, then what it produces.

Input→Process→Output
StageQuestion to askAdmission example
InputWhat data is needed?Student ID, name, department, mobile number; existing IDs.
ProcessWhat rules and calculations apply?Check blanks, uniqueness, and that mobile has exactly 10 digits.
OutputWhat result should be shown or stored?Admission confirmation or a helpful error message.

IPO example: attendance percentage

InputProcessOutput
Classes held = 40
Classes attended = 31		percentage = 31 / 40 × 10077.5%
“Eligible” if the requirement is 75%
Design tip: When requirements change, IPO helps locate the change. If the attendance requirement becomes 80%, the inputs remain the same; only the comparison rule changes.
Topic 4 · 30 minutes

Student Admission Module — requirements and design

This first UniFlow module creates a trustworthy student record. Correct validation here protects all later modules.

Required inputs

FieldPurposeExample valid value
Student IDUnique identifier for the studentUF2026001
Student nameName displayed on records and reportsPriya Sharma
DepartmentAcademic unit to which the student belongsComputer Science
Mobile numberContact number9876543210

Expected outputs

  • Success: saved student record and message such as “Admission completed for Priya Sharma (UF2026001).”
  • Failure: precise validation feedback, such as “Student ID already exists” or “Mobile number must contain exactly 10 digits.”

Admission validation rules

  1. Student ID must be supplied and must be unique.
  2. Student name and department must not be blank.
  3. Mobile number must contain exactly 10 numeric digits.
  4. The record is saved only when every rule passes.
Worked validation example:
Input: UF2026001, Priya Sharma, Computer Science, 9876543210
Suppose UF2026001 is not already stored. The mobile number has 10 digits. All rules pass, so the program stores the record and returns a confirmation.

Invalid case: Mobile = 98765AB210. It has letters, so the record is rejected and the program asks for a 10-digit numeric number.

Algorithm vs. pseudocode

AspectAlgorithmPseudocode
MeaningA clear, ordered description of how to solve a problem.A structured, code-like way to express an algorithm without using a programming language.
Writing styleUsually written in simple numbered sentences.Uses keywords such as START, IF, ELSE, and END IF.
PurposeHelps people understand the solution logic.Helps programmers translate the logic into a program later.
Example instruction“Check whether the mobile number has 10 digits.”IF mobile is not exactly 10 digits

Algorithm: admit a student

  1. Start the admission process.
  2. Accept the student ID, student name, department, and mobile number.
  3. Check whether all required details have been entered.
  4. Check whether the student ID is already used by another student.
  5. Check whether the mobile number contains exactly 10 digits.
  6. If any check fails, show the relevant error message and do not save the record.
  7. If all checks pass, save the student record and display an admission confirmation.
  8. End the admission process.

Pseudocode: admit a student

START
READ studentId, studentName, department, mobile
IF any required field is blank
    DISPLAY "All fields are required"
ELSE IF studentId already exists
    DISPLAY "Student ID must be unique"
ELSE IF mobile is not exactly 10 numeric digits
    DISPLAY "Mobile number must contain exactly 10 digits"
ELSE
    SAVE student record
    DISPLAY "Admission completed"
END IF
END
