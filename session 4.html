🗝️ 4. What Is a Cryptographic Key?

Think about a physical lock.

🔒 The lock is the security mechanism.

🗝️ The key is what lets an authorized person operate the lock.

In cryptography, a key is data used by a cryptographic algorithm to control the transformation of information.

⚠️ Important: A cryptographic key is not simply “the password.” Different cryptographic systems use keys in different ways.

🧠 2A. Cryptography: The Technical View

Technical definition: Cryptography is the study and application of mathematical techniques used to provide confidentiality, integrity, authentication and related security properties.

Algorithm

A precisely defined mathematical procedure that transforms data.

Examples: AES, ChaCha20, RSA, SHA-256, Ed25519.

Key

A secret or controlled value that parameterizes a cryptographic operation.

The security should depend on protecting the key, not on hiding the algorithm.

Security Property

Different primitives solve different problems.

Encryption → confidentiality; hashes → integrity/fingerprints; signatures → authenticity and integrity.

Important engineering principle: Modern cryptography normally follows the principle that the algorithm may be public while the key remains protected. Do not design a security system whose safety depends on keeping the algorithm secret.

🔐 3A. Encryption — Technical Detail

Encryption is a transformation designed so that someone without the required key cannot feasibly recover the protected plaintext.

Encryption: C = E(K, P) Decryption: P = D(K, C)

P = Plaintext

The original data: text, image, file, database record or network payload.

K = Key

The secret or controlled cryptographic value used by the algorithm.

C = Ciphertext

The encrypted representation sent or stored.

E / D

Encryption and decryption algorithms transform between plaintext and ciphertext.

Technical point: Encryption alone does not automatically guarantee integrity or authenticity. In modern applications, authenticated encryption such as AES-GCM or ChaCha20-Poly1305 is commonly preferred because it protects confidentiality and also authenticates the ciphertext.

🧱 3B. Block Ciphers, Stream Ciphers and AEAD

ConceptExplanationExample
Block cipherProcesses fixed-size blocks of data using a key and an encryption mode.AES
Stream cipherGenerates a keystream combined with plaintext, conceptually processing data as a stream.ChaCha20
Encryption modeDefines how a block cipher is safely applied to messages longer than one block.GCM, CTR, CBC
AEADAuthenticated Encryption with Associated Data: protects ciphertext and authenticates selected additional data.AES-GCM, ChaCha20-Poly1305
Why modes matter: Choosing AES does not by itself define a complete secure system. The mode, nonce/IV handling, authentication, key management and implementation all matter.

🔑 5B. AES — A First Technical Look

AES (Advanced Encryption Standard) is a symmetric block cipher with a 128-bit block size and key sizes of 128, 192 or 256 bits.

Block Size

128 bits = 16 bytes per block.

Key Sizes

128, 192 or 256 bits.

Structure

A substitution-permutation design operating through multiple rounds.

Real System

AES is normally used through a secure mode such as GCM rather than by simply encrypting each block independently.

Do not teach AES as “a complicated Caesar cipher.” AES uses carefully designed mathematical transformations and has been extensively analyzed by the cryptographic community.

🧮 6B. RSA and ECC — Why Students Should Know the Names

RSA

A public-key cryptosystem based on mathematical properties of large integers and modular arithmetic.

Used historically and still encountered in certificates and systems, though modern deployments often prefer elliptic-curve or modern signature schemes where appropriate.

ECC

Elliptic Curve Cryptography uses algebraic structures over finite fields.

It can provide strong security with relatively compact keys compared with traditional RSA at comparable security levels.

Key Establishment

Diffie–Hellman-style protocols allow parties to establish shared secret material over an insecure channel.

The shared secret can then be used with symmetric authenticated encryption.

High-level secure communication idea: Public-key mechanism → establish/agree secret ↓ Symmetric AEAD → protect bulk data efficiently

🧬 7A. Cryptographic Hash Functions — Technical Detail

A cryptographic hash function maps an input of arbitrary length to a fixed-length digest.

H : {0,1}* → {0,1}^n Example concept: Input: "HELLO" ↓ SHA-256 ↓ 256-bit digest

Preimage Resistance

Given a digest, finding an input that produces it should be computationally infeasible.

Second-Preimage Resistance

Given one input, finding a different input with the same digest should be difficult.

Collision Resistance

Finding any two different inputs with the same digest should be computationally difficult.

Avalanche Effect

A small input change should cause a substantial change in the digest.

Example: SHA-256 produces a 256-bit digest. Hashes are not “encrypted messages,” and there is no normal decrypt operation that recovers the original input.

✍️ 9A. Digital Signatures — Technical View

A digital signature binds a message to a signing key. In a typical scheme, the signer computes a signature using the private key and a verifier checks it using the corresponding public key.

Message ↓ Hash / message processing ↓ Sign with Private Key ↓ Digital Signature Verifier: Message + Signature + Public Key ↓ Verify ↓ Valid / Invalid
PropertyWhat it means
IntegrityVerification can detect whether the signed data has changed.
AuthenticityVerification can establish that a valid signature was produced by the holder of the corresponding private key, assuming the public key is correctly bound to that identity.
Non-repudiationOften discussed as a signature property, but its legal/organizational meaning depends on the system, key control, policy and applicable law.

🎲 12A. Randomness and Entropy

Cryptographic keys, salts, nonces and tokens often depend on unpredictable random values.

Weak randomness ↓ Predictable key/token ↓ Attacker can guess it ↓ Cryptographic protection can fail

CSPRNG

A cryptographically secure pseudorandom number generator is designed for security-sensitive random values.

Entropy

Informally, the unpredictability available to an attacker. More effective entropy means a larger search space.

Nonce

Often needs uniqueness rather than secrecy; the exact requirement depends on the algorithm and protocol.

Engineering lesson: Never invent your own random-number generator for cryptographic keys or security tokens.

🧪 12B. Cryptographic Attack Concepts — Defensive Understanding

Attack ConceptWhat the attacker tries to doDefensive Lesson
Brute ForceTry many possible keys/passwords.Use sufficiently strong keys and password protection.
Dictionary AttackTry likely human-chosen passwords.Use strong passwords/passphrases and password KDFs.
Offline GuessingTest guesses against stolen password verifiers.Use salted, expensive password hashing.
Man-in-the-MiddleInterfere with communication between parties.Authenticate endpoints/keys; use secure protocols.
Nonce ReuseExploit incorrect reuse of a nonce/IV where uniqueness is required.Follow the exact requirements of the cryptographic construction.
Key TheftObtain the actual secret/private key.Use access controls, secure storage and key lifecycle management.
These concepts are for defensive learning. Students should only test systems, accounts and cryptographic implementations they are explicitly authorized to test.

💻 13A. Mini Technical Example — Hash Verification

Suppose a teacher publishes a software file and also publishes its SHA-256 digest. A student can independently calculate the digest of the downloaded file and compare the values.

File A → SHA-256 → Digest A Downloaded File → SHA-256 → Digest B If Digest A == Digest B: No difference detected by this hash comparison Else: The file differs
Important: Hash equality does not prove that the file came from the teacher. To establish authenticity, use a trusted signature or another authenticated distribution mechanism.

🧠 13B. Mini Technical Example — Secure Password Verification

Registration: password ↓ generate unique salt ↓ password KDF(password, salt, work factor) ↓ store salt + verifier Login: entered password ↓ retrieve stored salt + parameters ↓ run same password KDF ↓ compare derived verifier ↓ allow / deny
Notice: The application does not need to store the user's original password.
