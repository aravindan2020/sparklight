UniFlow Student Admission Module — ELI10 Learning Session

🎯 Today's Big Idea

ELI10: Before asking a computer to solve a problem, we need to tell it exactly what to do. We can describe the solution in three useful ways: Algorithm = steps, Pseudocode = code-like English, and Flowchart = a picture of the steps.
Imagine telling a friend how to make tea. You can explain the steps, write them in a simple instruction format, or draw a picture showing the order. The tea recipe is the same — only the representation changes.

🔍 Algorithm vs Pseudocode vs Program

📋

Algorithm

A clear list of steps for solving a problem.

ELI10: Like a recipe written in normal language.

📝

Pseudocode

A structured, code-like description of the solution without using a specific programming language.

ELI10: Like a recipe written so that a programmer can easily convert it into code.

☕

Program

The actual solution written in a programming language such as Java.

ELI10: The computer-ready recipe.

RepresentationUniFlow Example
AlgorithmRead student details → display them → confirm registration.
PseudocodeINPUT student ID, name, department, mobile → DISPLAY details.
Java ProgramUses Scanner, variables, System.out.println(), etc.

3️⃣ Write the Pseudocode

ELI10: Pseudocode looks a little like programming, but it is not Java. We use simple words such as INPUT, DISPLAY, IF and ELSE. 
BEGIN

    INPUT StudentID
    INPUT StudentName
    INPUT Department
    INPUT MobileNumber

    DISPLAY "Student ID: ", StudentID
    DISPLAY "Student Name: ", StudentName
    DISPLAY "Department: ", Department
    DISPLAY "Mobile Number: ", MobileNumber

    DISPLAY "Registration Information Recorded Successfully"

END

Why not write Java immediately?

Because the logic should be correct before we worry about Java syntax such as Scanner, data types, semicolons and braces.

🧪 Quick Student Challenge

Question: Which one is easiest for a beginner to understand first?

Good starting point! The algorithm explains the solution as simple steps.
Pseudocode is useful after the algorithm because it prepares the logic for coding.
A program is the final implementation. It is easier when the logic is already clear.

Think: If you receive a new UniFlow requirement tomorrow, what should you create first?

Start by understanding the problem and designing the solution. Then create the algorithm, pseudocode/flowchart, and finally the Java program.
