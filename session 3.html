⚔️ 3. Authentication vs Authorization

These two words sound similar. But they answer two different questions.

Authentication

"WHO ARE YOU?"

Authorization

"WHAT ARE YOU ALLOWED TO DO?"

Feature Authentication Authorization
Main Question Who are you? What can you do?
Example Enter username + password Access student records
Happens Usually before authorization After identity is established
ELI10 Show your school ID Teacher decides which room you can enter
Security Goal Verify identity Control permissions

🧠 Memory Trick

Authentication = WHO?

Authorization = WHAT?

📊 5. Weak Password vs Strong Password

Property Weak Password Stronger Password
Length Very short Longer
Predictability Easy to guess Harder to predict
Personal information May contain name/birthday Avoids obvious personal information
Reuse Same password everywhere Unique for important accounts
MFA Usually absent Can be combined with MFA
Security Lower Higher
💡 Good habit: Use long, unique passwords or passphrases and use a reputable password manager when appropriate.

🧠 6. How Can Weak Passwords Become a Problem?

Concept ELI10 Explanation Simple Idea
Guessing Trying likely passwords "Maybe the password is 123456."
Credential Stuffing Trying leaked credentials on other services "Maybe they reused the same password."
Password Spraying Trying a small number of common passwords across many accounts One common key tested against many doors
Phishing Tricking a person into giving credentials Fake login page
Shoulder Surfing Watching someone enter credentials Looking over someone's shoulder
⚠️ These concepts should be studied for defensive education. Never attempt unauthorized access to another person's account.

💡 7. Five Password Security Stories

Example 1 — The Easy Lock

Ravi uses a very simple password that is easy to predict.

🧠 Lesson: Predictable passwords create unnecessary risk.

Example 2 — One Key for Every Door

A student uses the same password for email, shopping and social media.

🧠 Lesson: Password reuse can increase the impact if one password is compromised.

Example 3 — The Fake Teacher

Someone sends a message pretending to be a teacher and asks for the student's password.

🧠 Lesson: This is a social-engineering warning sign.

Example 4 — The Old Key

A person never changes or reviews credentials after learning that an account may have been compromised.

🧠 Lesson: Account recovery and credential management matter.

Example 5 — The Extra Lock

A user enables multi-factor authentication.

🧠 Lesson: Even if one factor is compromised, another factor can provide an additional security layer.

🔐 12. How Should Passwords Be Stored?

Imagine a school has 100 students.

The teacher should not write everyone's secret password on a public board.

Similarly, applications should not simply store users' plain-text passwords.

Instead, password storage should use appropriate password hashing mechanisms.

Storage Approach ELI10 Meaning Security
Plain Text Writing the secret directly ❌ Unsafe
Encrypted Password Secret is transformed and can be decrypted with a key ⚠️ Different purpose from password hashing
Hashed Password Store a derived value rather than the original password ✅ Better approach
Password Hash + Salt Use a unique random value with password hashing ✅ Stronger protection
Modern Password Hashing Use a password-specific adaptive hashing scheme ✅ Recommended design

⚔️ 14. Hashing vs Encryption vs Encoding

Feature Hashing Encryption Encoding
Main Purpose Derive a fixed representation / verify integrity or credentials Protect information so it can be recovered with a key Represent data in another format
Normally Reversible? No Yes, with the appropriate key Yes
Secret Key Required? Password hashing uses salt and algorithm parameters Yes, in encryption systems No
Example Use Password verification Confidential data Data representation

🤯 19. Common Student Confusions

Students May Think Correct Understanding
Password = Authentication A password is one possible authentication factor.
Authentication = Authorization Authentication asks WHO; authorization asks WHAT they can do.
OTP = Password forever An OTP is designed for limited or one-time use.
Hashing = Encryption They serve different purposes.
Long password alone solves everything Account security also depends on MFA, phishing resistance, recovery and other controls.
If I know the username, I can enter Knowing an identity identifier is not proof of identity.
